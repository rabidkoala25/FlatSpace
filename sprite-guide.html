Sprite drawing guide

Pixilart guidance for every Flatspace part: size, the current art, a starter PNG, the outline from top to bottom, what to draw and ideas for later. This page reads the game's own files, so sizes and pictures stay correct as parts change. The written notes come from art/sprite-notes.js.

How to draw a sprite

  1. Find the part below and download its starter PNG. It's the part's outline at the exact size, filled with metal 4 and outlined in metal 1, so you can draw straight over it. You can also start a blank drawing at the size listed.
  2. Open it in Pixilart and draw using only the palette colours below.
  3. Export as PNG at 1× (original size, not scaled up) and save it as art/png/<id>.png.
  4. Run node tools/png2sprite.js art/png/<id>.png. It writes art/sprites/<id>.js, or stops and names any pixel that isn't a palette colour.
  5. Add the new file to index.html (with the ?v= version), run node tests/run.js, then reload this page to see your sprite under Your pixel art.

Record drawing time with Lapse, and keep art under 30% of your Terra hours.

  • 16 art pixels per metre. The sizes below are already worked out. tests/test_sprites.js fails if a part's sprite is the wrong size, which catches a PNG exported at 10×.
  • Flat base tones, no shading. The game lights every sprite from the real sun, 2 tones darker in shadow to 1 tone lighter in full sun, plus a highlight pixel on metal. Shading you draw yourself would be doubled.
  • Leave room for the lighting: use mostly middle tones (metal 3–5, orange 2–4), so the light can go both ways.
  • A 1 px outline in metal 0 or 1 keeps parts readable against the sky.
  • Engines: the bottom quarter of the rows glows orange when firing, so put the bell's wide end there.
  • Tanks: paint the hull with the skin markers, so one drawing works for every skin.
  • Draw parts upright, top of the part at the top. Side parts (fins) have their root on the left; the game mirrors them.
